# 프로젝트 폴더 구조와 리팩토링

## 폴더 구조가 필요한 이유

프로젝트 규모가 커질수록 파일 수가 많아지기 때문에 역할에 따라 폴더를 구분하여 관리하는 것이 중요하다.

폴더 구조를 정리하면 원하는 파일을 쉽게 찾을 수 있고, 유지보수와 기능 확장이 편리해진다.

또한 여러 명이 함께 개발하는 상황에서도 코드의 위치를 쉽게 파악할 수 있다는 장점이 있다.


## 주요 폴더 역할

### pages

페이지 단위 컴포넌트를 관리하는 폴더이다.


- HomePage
- AdminPage


### components

여러 페이지에서 재사용할 수 있는 컴포넌트를 관리하는 폴더이다.


- Navbar
- ProductItem


### store

Zustand와 같은 전역 상태 관리 파일을 저장하는 폴더이다.

### apis

서버와 통신하는 API 관련 코드를 관리하는 폴더이다.

### styles

CSS 파일을 관리하는 폴더이다.

### assets

이미지, 아이콘 등 정적 파일을 관리하는 폴더이다.



## 프로젝트 리팩토링

이번 주차에는 프로젝트 구조를 정리하며 리팩토링을 진행하였다.

기존에는 기능 구현에 집중하면서 파일과 코드가 분산되어 있었지만, 역할에 따라 폴더를 구분하여 관리하도록 수정하였다.

또한 반복적으로 사용될 수 있는 UI는 공통 컴포넌트로 분리할 수 있도록 구조를 정리하였다.

스타일 파일 역시 관리 편의성을 위해 정리하였으며, 역할이 크게 겹치던 App.css와 index.css는 하나의 파일로 통합하여 관리하도록 변경하였다.

API 관련 코드도 기능별로 분리하여 관리할 수 있도록 구조를 개선하였다.
