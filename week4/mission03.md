# 상태 관리(State Management)

## 상태(State)란?

상태(State)는 사용자 입력이나 화면 변화에 따라 변경되는 데이터를 의미한다.

쇼핑몰 프로젝트에서는 장바구니, 상품 수량, 재고, 검색어 등이 상태가 될 수 있다.

기존에는 useState를 사용하여 컴포넌트마다 상태를 관리했지만, 프로젝트 규모가 커질수록 여러 컴포넌트가 같은 데이터를 공유해야 하는 상황이 발생한다.



## 상태 관리가 필요한 이유

상태 관리가 필요한 이유는 데이터의 일관성을 유지하기 위해서이다.

예를 들어 장바구니 정보는 상품 목록, 장바구니 페이지, 헤더 등 여러 컴포넌트에서 함께 사용된다.

각 컴포넌트가 상태를 따로 관리하면 데이터가 서로 달라질 수 있기 때문에 상태를 한 곳에서 관리하는 것이 효율적이다.

또한 상태 관리를 사용하면 유지보수가 쉬워지고 데이터 흐름을 파악하기도 편리해진다.



## Context API

React에서는 Context API를 통해 여러 단계의 컴포넌트를 거치지 않고 데이터를 공유할 수 있다.

이를 통해 Props Drilling 문제를 줄일 수 있다.

하지만 프로젝트 규모가 커지고 상태 종류가 많아지면 Context만으로 관리하기 어려운 경우가 있어 상태 관리 라이브러리를 사용하기도 한다.


## 상태 관리 라이브러리

대표적인 상태 관리 라이브러리는 다음과 같다.

- Redux : 대규모 프로젝트에 적합하지만 설정이 복잡하다.
- Recoil : React와 비슷한 방식으로 사용할 수 있다.
- Jotai : 가볍고 단순한 구조를 가진다.
- Zustand : 사용법이 간단하고 설정이 적다.

각 라이브러리는 장단점이 있지만 프로젝트 규모와 목적에 따라 적절한 도구를 선택하는 것이 중요하다.



## Zustand를 선택한 이유

이번 쇼핑몰 프로젝트에서는 Zustand를 사용하였다.

Redux에 비해 설정이 간단하고 학습 난이도가 낮으며, 전역 상태를 쉽게 관리할 수 있다는 점이 장점이라고 느꼈다.

특히 장바구니, 상품 수량, 재고 정보처럼 여러 컴포넌트에서 사용하는 데이터를 관리하기에 적합하다고 생각하였다.
